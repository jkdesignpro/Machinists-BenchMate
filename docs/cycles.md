# G-code cycle generators: sources and decisions

Tools in the **G-code cycles** group: `cycdrill` (G81, G82, G83, G73, G84),
`cyctmill` (thread milling), `cycthread` (G76 or G92 lathe threading with an
infeed table), `cyctaper`, `cycgroove` (groove and cut-off with CSS),
`cycbroach` (keyway broaching on a lathe or mill) and `cycg71` (G71/G70 from a
simple profile).

Code: formulas in `core/src/cycles.rs`; program text, moves for the backplot
and the time estimate in `core/src/gcode.rs`; screens in `app/cycles.js`.
Golden-output tests: `core/src/gcode/tests.rs` with the expected programs in
`core/src/gcode/golden/*.nc` (rewrite with `BLESS=1 cargo test`, then review
the diff by hand).

All sources below were read on **2026-11-10**. Nothing was copied from any
other calculator; the program layouts and wording are BenchMate's own.

## Rules every program follows

- A warning header: generated by BenchMate, check every line against your
  control manual, prove out in single block with low rapid and feed override.
  The control dialect and the units are printed in the header.
- `G21` (mm) or `G20` (inch) in the first motion block.
- Coordinates, R planes, depths, feeds and leads always carry a decimal point
  (`X10.0`, `Z-3.175`, `F150.0`): some controls read `X10` as 10 least input
  increments (0.010 mm). Integer words stay integers where the format says so:
  `S`, `T`, `H`, `D` (register), `M`, `N`, `O`, Haas `A` (tool angle), and the
  Fanuc-style G76 `P` and `Q` words, which are written in the least input
  increment (0.001 mm or 0.0001 in) without a decimal point. Fanuc-style dwell
  `P` is milliseconds without a decimal point.
- Comments are upper case in parentheses, without nested parentheses.
- Output is deterministic: the same inputs always give the same text.
- A cycle is only generated for a control whose syntax is confirmed from the
  maker's public manual or two independent public sources. The other controls
  are listed in the control drop-down as "not yet supported" and cannot be
  selected.

"Generic ISO 6983 / Fanuc-style" means the Fanuc-compatible word layout and,
on lathes, G-code system A (G50 speed clamp, G92 threading cycle, G98/G99
feed per minute/revolution). Lathes set to system B or C use G92 for the speed
clamp and G78 for the threading cycle [IMD-SYS]; BenchMate does not output
those yet.

### Why the other controls are not supported yet

- **Mitsubishi M70/M80/M800.** The maker's programming manuals are public
  (machining centre IB-1501277/IB-1501278, lathe IB-1501275/IB-1501276). The
  copy that could be read (IB-1501278-B, volume 2/2) only lists the fixed
  cycles in its contents; the cycle pages are in volume 1/2, which could not
  be fetched. Mitsubishi also offers several G-code lists, so the format
  depends on a parameter. To do: read section 13.1 of IB-1501277 and the
  lathe compound cycles in IB-1501275.
- **Siemens 840D sl ISO mode.** Siemens publishes an "ISO dialects" manual;
  it could not be fetched for this round.
- **Heidenhain (ISO programming).** Heidenhain uses its own cycle numbers
  (G200 series) rather than G81-G84; not checked.
- **Okuma OSP.** OSP lathes use LAP cycles and the milling canned cycles
  differ from Fanuc; not checked.

## Formulas and checks

| Formula | Where | Check |
|---|---|---|
| Constant-volume infeed from the first cut: depth_n = d1 sqrt(n), steps at least the minimum cut, then the finish allowance | `infeed_by_first_cut` | [HAAS-G76] equation; test of the sqrt(n) sequence and the minimum-cut clamp |
| Constant-volume infeed over n passes: depth_i = ap sqrt(c_i / (n - 1)) | `infeed_by_passes` | [ISCAR] worked example, all six passes within 0.006 mm (catalogue rounds to 0.01) |
| Constant depth, custom list | `infeed_constant_depth`, `infeed_custom` | hand cases |
| Thread depths 0.613435 P and 0.541266 P | `thread_depth_external/internal` | M10 x 1.5 d3 = 8.160 mm (ISO 965-1 table value) |
| Tool-centre path radius (D - d)/2 inside, (Dr + d)/2 outside | `thread_mill_path_radius` | hand cases |
| Tool-centre feed F x (D -/+ d) / D | `thread_mill_centre_feed` | [HPC] 2.8 and 13.8 IPM, [TRV] 5.76 IPM |
| Feed along the helix F sqrt(1 + (P / 2 pi r)^2), lead angle atan(P / 2 pi r) | `helix_path_feed`, `helix_lead_angle_deg` | 45 degree case |
| CSS rpm n = 1000 Vc / (pi D) or 12 V / (pi D), clamped | `css_rpm` | [SAN] 200 m/min at 50 mm = 1273.24 rpm; 500 SFM at 2 in = 954.93 rpm |
| CSS plunge time: (D0² - D1²) / (4 f k) above the clamp diameter k / n_max, (D/2) / (f n_max) below | `css_plunge_time_min` | hand example 50 mm to 0, 0.1 mm/rev, 150 m/min, 2500 rpm = 0.149998 min; equal to direct numerical integration of dr / (f n) |
| Tapping feed = pitch x rpm | `tap_feed` | [HAAS-TAP] 1.75 x 500 = 875; 500 / 13 x 25.4 |

## Decisions

- **Text generation in Rust.** The program text is built in `gcode.rs`, so
  the golden tests run with `cargo test` and the app shows exactly the tested
  output. The app passes the inputs through the shared buffer and reads the
  text back through `str_ptr`.
- **Dwell.** Fanuc-style: `P` in milliseconds, integer ([MIFM]); Haas reads an
  integer P as milliseconds too ([HAAS-MW]) but its documented canned-cycle
  form is seconds with a decimal point, so Haas output uses seconds.
- **Rigid tapping.** Generic: `M29 S..` after G43 and before G84 (no M03),
  as in [MIFM] and [CNCC]. Some Fanuc-style machines use G84.2 or a
  parameter instead; check your manual. Haas: no M29, needs the rigid tapping
  option ([HAAS-TAP]). Floating holders: same feed (pitch x rpm), with a
  comment to check the holder maker's advice.
- **Peck clearance** (Fanuc parameter 5114/5115, Haas setting 22) is a
  control value: the program does not set it; the time estimate assumes
  0.5 mm (0.02 in).
- **Thread milling direction** (BenchMate derivation, tested in
  `threadmill_geometry`): with M03 the cutter turns clockwise seen from +Z.
  Inside a hole the cutting point is outward of the tool centre, so a
  counter-clockwise path (G03) moves against the tooth motion at the contact
  point: climb milling. Outside a boss the contact is inward, so climb is
  clockwise (G02). A right-hand helix rises when the path turns
  counter-clockwise. G41 with climb, G42 with conventional. Lead-in and
  lead-out are 90 degree arcs tangent to the thread circle, a quarter pitch of
  Z each; for an external thread the lead arcs curve the other way (S-shaped
  entry) so they stay outside the part. With compensation the programmed
  radii are the contour (thread) radius and the lead radius plus the tool
  radius, so the tool centre follows the same path as without compensation.
- **Thread milling feed with G41/G42.** Some controls apply F to the
  programmed contour, others to the tool centre; the program says so in a
  warning. F is the tool-centre feed in the plane of the arc.
- **G76 infeed.** A Fanuc-style G76 always cuts constant volume from the
  first cut (Δd sqrt n) with the minimum cut and finish allowance from the
  first block; the screen only allows that infeed for G76. Haas G76 also
  offers constant depth (P3). Other infeeds (by number of passes, custom
  lists) are output as one G92 block per pass. The pass table for G76 is
  BenchMate's model of what the control will cut; the control computes the
  real passes.
- **G76 finishing passes.** `m` (first two digits of P) = 1 + spring passes:
  the finishing pass is repeated m times ([CTE] "number of finish passes").
  Haas G76 has no spring-pass word: spring passes are added as G92 blocks at
  full depth.
- **Flank infeed with G92.** Each pass starts at Z shifted by (depth left) x
  tan(infeed angle) toward the chuck, so the tool follows the leading flank
  and the last pass is on the nominal start Z. Tapered and multi-start threads
  are not generated.
- **Pull-out (chamfer)** in G76 P is entered in leads (0 to 9.9) and written
  as tenths.
- **Taper program.** Stock is the back diameter (external) or a bore at the
  back diameter (internal). Each roughing pass follows the cone back so the
  finish allowance is even. Nose radius compensation is optional; without
  it a warning says the taper will be slightly off size.
- **Groove.** Z is the insert's front (+Z) corner. Wide grooves are cut with
  several plunges, step = 80 % of the insert width unless entered.
- **Keyway broaching.** The spindle must be oriented and locked; the code for
  that is machine specific (often M19, but not always), so BenchMate writes a
  comment instead of an M-code.
- **G71 profile.** Straight lines only, type I (no undercuts). The roughing
  moves on the backplot and in the time estimate are BenchMate's model:
  levels at the depth of cut, each to the offset profile, then a pass along
  the offset profile and the G70 finish.
- **Cycle time.** Feed moves at the programmed feed (lathe feeds per
  revolution converted with the rpm at each point along the move, CSS
  included); rapids at the rapid rate from the screen or the active machine
  profile (new optional "Rapid traverse rate" field); dwells. Tool changes,
  acceleration and block processing are not included.
- **Machine checks.** The highest rpm and the highest feed per minute in the
  program are compared with the active machine profile.
